# 🧪 mio 功能测试通用提示词（实机回归集）

> 人工实机回归测试集：在扩展侧边栏粘贴「任务目标」运行，对照「验收标准」判定通过，失败时贴日志驱动修复。

> ⚠️ 每个场景 2 个任务（基础/进阶）。建议按场景全跑一轮回归：导航+搜索+提取 → 表单+发送验证 → 恢复兜底 → 多标签页。

---

## 🚀 使用说明

| 步骤 | 操作 |
|------|------|
| 1 | 复制某任务的「任务目标」到侧边栏输入框，运行 |
| 2 | 任务完成后，对照「验收标准」逐条检查 |
| 3 | 不通过 / 异常时，把 onLog 输出贴回来 |
| 4 | 记录每个任务的「失败信号」，回归时重点盯 |

> 任务目标均为通用自然语言，可替换网站/关键词复用。所有站点无需登录，避免账号依赖。

## 🌐 场景一：导航 + 搜索 + 提取

**验证点**：`navigate`、快照定位、`type`、`extract_text` 基础链路。

### 任务 1 · 基础

```
在必应搜索 "web agent 原理"，打开搜索结果的第一条链接，提取该页面正文的前 3 个要点。
```

**期望行为**：导航 → 搜索框输入 → 回车/点搜索 → 点击首条结果 → `extract_text`。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 导航 | 最终 URL 是搜索结果的落地页，非必应首页 |
| 点击 | 打开的是第一条结果，非广告/侧栏链接 |
| 提取 | 返回 3 个要点，内容与标题相关 |

**失败信号**：点了广告链接、提取到导航栏而非正文、在无结果时虚构 URL。

### 任务 2 · 进阶

```
在 GitHub 打开开源项目 vercel/next.js 的 README，提取该项目的核心特性和开始使用的命令。
```

**期望行为**：`navigate` 到仓库 → 可能需 `scroll` 到 README 正文 → `extract_text` 并归纳。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 定位 | 命中 README 正文区，非仓库文件列表 |
| 提取 | 特性 ≥ 3 条，含 1 条 install 命令 |
| 滚动 | 长页可滚到目标，不报「元素缺失」 |

**失败信号**：点进单个源文件、README 在下方却提前结束、滚动后定位漂移。

## 📤 场景二：表单 + 发送验证

**验证点**：`type`/`paste`、发送按钮点击、`verifySend` 闭环、重复点击守卫、`SEND_NOT_VERIFIED` 恢复。

> 此场景对应最近修复：paste 触发验证、wait 不破守卫、未确认发送不再静默成功。

### 任务 1 · 基础（已登录 DeepSeek 对话页）

```
向 DeepSeek 发送消息："用一句话解释什么是 Agent Runtime"。等回复生成后，提取回复的第一句话。
```

**期望行为**：输入 → 点一次发送 → 等待回复 → `extract_text`。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 发送次数 | 发送按钮只被点击 1 次 |
| 消息发出 | 日志出现「发送已确认」，输入框已清空 |
| 回复生成 | 提取到一句关于 Agent Runtime 的解释 |
| 无恢复 | 未触发 `SEND_NOT_VERIFIED` recovery |

**失败信号**：发送按钮被连点多次、日志「发送未确认」误报、回复未生成却声明完成。

### 任务 2 · 进阶（长文本 + 追问）

```
在已登录的 DeepSeek 对话页，粘贴一段 200 字以上的技术说明发送，回复完成后立即追问"请展开第一点"，确认两条消息都已发出并都有回复，提取第二条回复的要点。
```

**期望行为**：`paste` 长文本 → 点发送 → 验证 → `type` 追问 → 再点发送 → 验证 → 提取。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| paste 发送 | paste 后只点 1 次发送即确认，非 3 连击 |
| 追问发送 | 第二条消息发出且有独立回复 |
| 验证闭环 | 两次发送各出现 1 次「发送已确认」 |
| 提取 | 第二条回复要点与追问相关 |

**失败信号**：paste 不触发验证（连点）、追问与回复错位、第二条回复未提取到。

## ⏳ 场景三：慢加载 / 缺失元素恢复

**验证点**：`wait`、`retry_snapshot`、`scroll_and_retry`、recovery 分层、NO_TOOL_CALLS 纠正。

### 任务 1 · 基础（延迟加载）

```
打开 open-meteo.com 的天气查询页（https://open-meteo.com），等待页面数据加载完成，提取城市搜索框右侧显示的当前温度。
```

**期望行为**：导航 → 数据未就绪时 `wait` → 重试快照 → 数据出现后提取。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 等待 | 日志含 wait / retry_snapshot，未提前失败 |
| 提取 | 拿到温度数值 |
| 恢复 | 若首轮元素缺失，recovery 动作 ≤ 2 次后成功 |

**失败信号**：元素延迟出现就放弃、recovery 耗尽仍找不到明明存在的元素、无等待直接报错。

### 任务 2 · 进阶（元素不在首屏）

```
打开 zh.wikipedia.org 的"浏览器扩展"词条页面，滚动到页面最下方，点击"目录"区块中的第一个条目链接，确认跳转到了对应章节。
```

**期望行为**：导航 → 滚动 → 定位下方元素 → 点击 → 校验 URL 锚点变化。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 滚动 | `scroll_and_retry` 或主动 scroll 到达目标 |
| 点击 | 命中目录首条目，非文章正文 |
| 跳转 | URL 出现 `#` 锚点变化 |

**失败信号**：点击后 URL 无变化、滚动越界找不到元素、点击命中错误元素。

## 🗂️ 场景四：多标签页协作

**验证点**：`tab` 工具（open/list/switch/close）、跨 tab diff 抑制、跨页复制粘贴。

### 任务 1 · 基础

```
新开一个标签页打开 example.com，切换到它读取页面标题，然后关闭该标签页，回到原来的标签页。
```

**期望行为**：`tab` open → switch → `extract_text` → close → 回原 tab。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 开/切 | 快照正确显示新 tab 内容（Tab i/n） |
| 读标题 | 提取到 "Example Domain" |
| 关/回 | 关闭后回到原 tab，快照恢复原页面 |

**失败信号**：tab 切换后快照仍是旧页、关闭后上下文错乱。

### 任务 2 · 进阶（跨页复制粘贴）

```
在必应搜索 "agent runtime"，记下第一条结果的标题。新开标签页打开 github.com 主页，切回必应，把该标题粘贴到 GitHub 的搜索输入框并搜索，确认出现搜索结果。
```

**期望行为**：搜索 → 记录 → tab open → tab switch → 跨 tab 复制 → 粘贴 → 搜索。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 跨 tab | 标题正确从必应带到 GitHub |
| 粘贴 | 搜索框内容 = 原标题 |
| 结果 | 出现 GitHub 搜索结果页 |

**失败信号**：切换后拿到错误页内容、粘贴空内容、搜索无结果且 agent 虚构。

## 🔁 场景五：跨站搬运 + 会话记忆（memo）

**验证点**：`memo` 工具（set/get/list）、跨 tab 数据保留、replan 不丢数据、planner 跨站规划。

> 此场景对应 memo 会话记忆：跨页/长任务数据显式保存，不依赖会被裁剪的对话历史。

### 任务 1 · 基础（邮箱验证码 → 登录）

```
新开标签页打开 https://www.163.com（或你的邮箱），找到登录入口；同时准备好一个临时邮箱收到的验证码页面，把验证码用 memo 保存，再切到目标站登录页，从 memo 读取验证码并输入，确认验证码正确填入。
```

> 若无可用邮箱/验证码，可用一个更简单的替代：
> 在必应搜索 "openai"，把第一条结果标题 memo 保存；新开标签页打开 example.com，切回必应，从 memo 读取标题并确认它与当前第一条结果一致。

**期望行为**：`tab` open → `memo set` 保存 → `tab` switch → `memo get` 读取 → 输入/比对。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| memo 保存 | 日志出现 `memo → saved`（set 成功） |
| 跨 tab 读取 | 切页后 `memo get` 返回原值，非空/非虚构 |
| 数据正确 | 填入/比对的内容与源页一致 |

**失败信号**：切页后忘记 memo、从记忆中重打导致错值、`memo get` 返回空却继续。

### 任务 2 · 进阶（replan 后 memo 不丢）

```
在必应搜索 "mio browser agent"，把第一条结果标题 memo 保存为 title。故意让某个中间步骤失败（例如要求点击一个不存在的元素），观察 replan 后，再从 memo 读取 title，确认 replan 后 memo 数据仍然存在。
```

**期望行为**：`memo set` → 触发 replan → `memo get` 仍返回原值。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| replan 触发 | 日志出现「重新规划」 |
| memo 保留 | replan 后 `memo get` 返回原标题 |
| 不重提取 | replan 后不再重复提取已 memo 的数据 |

**失败信号**：replan 后 memo 丢失、replan 重新提取已保存数据、数据被改。

## 👁️ 场景六：视觉兜底（vision 坐标点击）

**验证点**：`vision_locate` 恢复动作、坐标解析（`x:n, y:n`）、`click_at` 按坐标点击。

> 前提：设置里启用 Vision 并配置 vision 模型。此场景验证「DOM 找不到但视觉能看到」的兜底链路。

### 任务 1 · 基础（canvas 目标坐标点击）

```
打开一个包含 canvas 交互元素或 SVG 图形按钮的页面（如 https://www.draw.io 画布，或任意带 canvas 图标的站），给一个正常 DOM 定位会失败、但肉眼可见的点击目标（例如画布内的某个图形），让 mio 点击它，观察是否通过视觉定位后按坐标点击成功。
```

> 若无 canvas 站，可用本地测试页：加载 tests/test-page.html，目标描述用「页面中部的 canvas 区域」，验证 `click_at` 坐标点击真实命中。

**期望行为**：DOM 定位失败 → `vision_locate`（含坐标）→ 日志出现 `click_at`。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| vision 触发 | 恢复日志出现 `vision_locate` |
| 坐标解析 | 恢复事件 reason 含坐标（如 `(512, 360)`） |
| 坐标点击 | 出现 `click_at` 工具调用且成功 |

**失败信号**：视觉模型报「可见」但无坐标、agent 拿到坐标却仍用快照索引失败、click_at 报无元素。

### 任务 2 · 进阶（无坐标降级）

```
在任意普通页面（如 example.com），给 mio 一个 DOM 快照里确实不存在的目标（如"页面右下角不存在的按钮"），确认视觉兜底正确报告「不可见」，而不是编造坐标继续乱点。
```

**期望行为**：`vision_locate` → 不可见 → 步骤诚实失败。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 不可见判定 | 恢复日志 reason 含「不可见」 |
| 无坐标 | 未编造 `x:n, y:n` |
| 诚实失败 | 步骤失败而非乱点 |

**失败信号**：视觉模型对不存在的目标编造坐标、agent 用假坐标乱点、把「不可见」误报为可见。

## 🖼️ 场景七：跨域 iframe（扩展层真机验证）

**验证点**：`getAllFrames` 枚举跨域 frame、按 `frameId` 路由 snapshot 与动作、iframe 内元素可操作。

> 同源 iframe（framePath 定位）已被 CDP 测试覆盖；跨域 iframe（如 Gmail 富文本、嵌入表单）走 `getAllFrames` + `frameId` 路由，需在扩展运行时真机验证。

### 任务 1 · 基础（含 iframe 的普通页面）

```
打开一个包含 iframe 的页面（如 https://www.w3schools.com/html/html_iframe.asp，或任意含嵌入内容的站），找到 iframe 内的一个可点击元素并点击它。
```

**期望行为**：`snapshot` 收集 iframe 元素（带 frameId）→ 定位 → 按 frameId 路由点击。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 快照 | iframe 内元素出现在快照（debug 显示 element 带 frameId） |
| 操作 | 能定位并点击 iframe 内元素 |
| 结果 | 点击生效（iframe 内容响应） |

**失败信号**：iframe 元素缺失、定位到主 frame 的错元素、点击后 iframe 无响应。

### 任务 2 · 进阶（嵌入表单）

```
打开一个含嵌入表单 iframe 的页面（如 Google Forms 嵌入页，或任意用 iframe 嵌表单的站），在 iframe 内的输入框输入一段文字，并提交。
```

**期望行为**：`snapshot` 收集 iframe 输入框 → `type` 按 frameId 路由 → 提交。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 定位 | iframe 内输入框被快照收录并可定位 |
| 输入 | 文字正确填入 iframe 输入框 |
| 提交 | 提交动作到达 iframe 表单 |

**失败信号**：iframe 输入框无法定位、输入落空、提交无反应、报「无法与页面通信」。

## 📝 场景八：表单自动填充（form_fill）

**验证点**：`form_fill` 批量填表（语义字段匹配）、select/checkbox、提交按钮识别、v0.1.39 修复项（React checkbox 同步、空 select 值、表单作用域、弱关键词 ok、多词 label 边界）。

> 此场景对应 form_fill 功能 + v0.1.39 边界加固。核心：**一次调用填完表单**，agent 不应逐字段 type。

### 任务 1 · 基础（本地测试页登录表单）

```
加载本地测试页（打开 tests/test-page.html），用表单填充的方式填写登录表单：用户名 alice、密码 s3cret、城市选上海、勾选同意条款，然后提交登录。
```

**期望行为**：一次 `form_fill`（或至多 1-2 步）完成全部字段 → submit 点击登录按钮。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 语义匹配 | `username/password/city/agree` 被识别并填充对应字段，非逐字段 type |
| 下拉 | 城市 select 选中「上海」，未选中占位「请选择城市」 |
| 复选框 | 同意条款被勾选，页面状态同步 |
| 提交 | 提交按钮被点击（`__ffSubmitted` 计数 +1），且只点 1 次 |
| 步骤数 | 填表+提交合计 ≤ 3 步（理想 1 步） |

**失败信号**：agent 逐字段 `type` 替代 `form_fill`、城市选中占位项、checkbox 勾了但页面状态没变（React 同步问题）、提交点到别的按钮。

### 任务 2 · 进阶（真实站表单 + 多表单作用域）

```
打开一个含多个表单或复杂表单的页面（如 https://www.w3schools.com/html/html_forms.asp 的表单示例区，或任意注册/搜索/筛选表单站），用表单填充填写主表单的字段并提交。
```

**期望行为**：`form_fill` 识别字段语义 → 填充 → 提交作用域限定在**主表单**内，不点到同页其它表单的按钮。

**验收标准**

| 项 | 通过条件 |
|----|----------|
| 字段识别 | 字段按 label/placeholder 语义匹配（含中文同义词） |
| 多表单 | 页面含 ≥2 个表单时，提交落在已填字段所在表单 |
| 空值安全 | 若 select 有占位空选项，不会被误选为有效值 |
| 弱关键词 | 页面若有「OK」类按钮，不会被当作提交（登录/注册/提交按钮才被点） |
| 部分失败 | 某字段找不到时返回明细，已填字段保留 |

**失败信号**：提交点到错误表单、把「OK/确定」按钮当提交、空占位选项被当作选择结果、字段未匹配却报成功。
